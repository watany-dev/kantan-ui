## フェーズ1: 高優先度（コア機能の信頼性）

### 1.1 出力APIテスト `e2e/output-api.spec.ts`

**対象**: `kt.write()`, `kt.title()`, `kt.header()`, `kt.subheader()`, `kt.text()`, `kt.divider()`, `kt.html()`

**実装内容**:

| テストケース | 検証内容 | 工数目安 |
|-------------|---------|---------|
| write - 文字列出力 | `.kt-write`要素が生成され、テキストが表示される | S |
| write - 数値出力 | 数値が文字列に変換されて表示される | S |
| write - 真偽値出力 | `true`/`false`が文字列として表示される | S |
| write - HTMLエスケープ | `<script>`などがエスケープされる | S |
| title | `h1.kt-title`要素が生成される | S |
| header | `h2.kt-header`要素が生成される | S |
| subheader | `h3.kt-subheader`要素が生成される | S |
| divider | `hr.kt-divider`要素が生成される | S |
| html - 静的HTML出力 | 生のHTMLがそのまま挿入される | S |
| 複合テスト | 複数の出力APIを組み合わせた順序確認 | M |

**必要な準備**:
- 出力API専用のデモページ作成（`examples/output-demo.ts`）

### 1.2 WebSocket再接続テスト `e2e/websocket-reconnect.spec.ts`

**対象**: WebSocket切断・再接続、ネットワークエラー回復

**実装内容**:

| テストケース | 検証内容 | 工数目安 |
|-------------|---------|---------|
| 接続切断検出 | サーバー切断時にクライアントが検出する | M |
| 自動再接続 | 切断後に自動的に再接続を試行する | M |
| 再接続後の状態復元 | 再接続後にセッション状態が維持される | M |
| 再接続リトライ上限 | `maxReconnectAttempts`後に再接続を停止 | M |
| 指数バックオフ | 再接続間隔が徐々に増加することを確認 | M |

**技術的課題**:
- Playwrightで意図的にWebSocket接続を切断する方法の調査
- サーバー側での切断シミュレーション
